## Purpose

Record genuine, source-verified bugs found during a systematic audit of the
Dopamine v3 codebase. This is **not** a style review — formatting, naming, and
type-only concerns are explicitly out of scope. Every finding below was
confirmed by reading the actual code and its call sites.

## Scope (in / out)

- **In:** runtime defects — boundary/edge cases, error handling, resource
  lifecycle, async/state bugs, SQL correctness, IPC/Electron lifecycle.
- **Out:** code style, naming, missing type annotations, theoretical concerns
  with no runtime impact, and the pre-existing data-dependent runtime warnings
  already observed during the smoke test (empty `file://` accent-color load,
  "Could not find MIME for Buffer" on some album artwork) — those are cosmetic
  and not part of this audit's defect set.

## Methodology

1. **Orient & static sweep** — mapped the source tree; grep for known defect
   patterns (empty catches, `parseInt` without radix, timer cleanup,
   `JSON.parse`, SQL interpolation).
2. **Parallel deep audit** — three exploration passes over playback/audio,
   data/indexing, and the Electron main process.
3. **Independent verification (rubber-duck pass)** — every candidate was
   re-checked against the real code and call sites by an independent reviewer.
   This step **rejected 5 false positives** and **recalibrated 2 severities
   down** (see below) — candidates are not reported here unless they survived
   verification.

Grounded in the bug-hunter method (Regehr's scientific loop; Agans; Feathers;
Zeller) — confirm the bug, trace bad values to their origin, and prefer the
calibrated explanation over the dramatic one.

## Summary

- **11 confirmed bugs**: 3 Medium, 8 Low. No High-severity defects survived
  verification.
- **5 false positives** rejected during verification (documented for audit
  trail).
- **Theme of the real findings:** non-deterministic resource lifecycle (timers,
  subscriptions, DB connections, workers) and string-built SQL that mishandles
  legitimate metadata characters. None are crash-on-launch or data-loss class.

## Detailed findings

### BUG-001 — Crossfade flag stuck after a failed preloaded `play()` (Medium)

- **File:** `src/app/services/playback/audio-player/crossfade-audio-player.ts`, lines 196–206 (flag set 199; catch 201–205). Resets only in `finishCrossfade()` (235) and `stopInternal()` (142).
- **Symptom:** `beginCrossfadeAsync()` sets `_isCrossfading = true`, then if `await this._nextAudio.play()` throws it logs and returns **without** resetting the flag. The crossfade watcher guard (`if (!this._preloadedTrack || this._isCrossfading) return`) then blocks all future crossfades until a full `stop()`. Aggravating factor: `_currentAudio.onended` suppresses `playbackFinished` while `_isCrossfading` is true (lines 75–79), so the current track can end **without the queue advancing**.
- **Class:** Error handling / state lifecycle.
- **Fix:** In the `catch`, reset `_isCrossfading = false`, restart the crossfade watcher, and fall back to normal next-track handling (or emit a playback failure).

### BUG-002 — SQL built by string interpolation breaks on apostrophes (Medium)

- **File:** `src/app/data/repositories/track-repository.ts`, lines 171–178: `WHERE t.AlbumKey${albumKeyIndex} = '${albumKey}'`.
- **Symptom:** `albumKey` derives from tag metadata (`track-filler.ts` 62–65 → `album-key-generator.ts` 7–16 → `data-delimiter.ts` preserves apostrophes). A legitimate album/artist with a `'` (e.g. *Sgt. Pepper's*, *Livin' on a Prayer*) produces malformed SQL and the album-artwork/data lookup fails. Reachable from normal playback/artwork paths (`metadata.service.ts` 60, 137–138 → `cached-album-artwork-getter.ts` 16–17).
- **Note on severity:** This is a local desktop app reading the user's own files, so it's a **correctness/robustness** bug, not a practical security exploit — hence Medium, not High. Sibling methods in the same file already bind parameters correctly (e.g. lines 355–358, 361–367).
- **Class:** SQL correctness.
- **Fix:** Use a bound parameter: `WHERE t.AlbumKey${albumKeyIndex} = ?` and `statement.all(albumKey)`.

### BUG-003 — Indexing worker: no error handler, not terminated on quit (Medium)

- **File:** `main.ts`, lines 554–570 (`ipcMain.on('indexing-worker', …)`).
- **Symptom:** A fresh `Worker` is spawned per IPC message, stored only in a local variable. It handles `message` and `exit` but **not** `error`; `will-quit` (487–489) only shuts down Discord. The worker normally self-exits after posting `"Done"` (`main/background-work/workers/indexing-worker.js` 27–30) and catches task-body errors (14–24), so this is **not** a guaranteed unbounded leak. The real exposure: an unhandled worker-level `error` (startup/top-level/rejected task) and the lack of termination of an in-flight worker on app quit. The renderer guards duplicate indexing via `isIndexingCollection` (`indexing.service.ts` 230–243), which bounds normal accumulation.
- **Class:** Resource lifecycle / error handling (IPC trust boundary).
- **Fix:** Track the active worker, ignore/queue concurrent requests, add `workerThread.on('error', …)`, and terminate any active worker in `will-quit`.

### BUG-004 — Rich-lyrics subscriptions accumulate across track changes (Low)

- **File:** `src/app/ui/components/now-playing/now-playing-lyrics/rich-lyrics/rich-lyrics.component.ts`.
- **Symptom:** `ngOnChanges` (43–49) calls `stopTimers()` then `startTimers()` on every `lyrics` input change. `startTimers()` (57–68) `.add()`s two subscriptions (`playbackSkipped$`, `playbackStarted$`); `stopTimers()` (103–113) clears only the `setInterval` timers, never the subscription. The `Subscription` is unsubscribed only in `ngOnDestroy` (52–55). Over a long session on the lyrics view, duplicate (cheap) callbacks and subscription objects accumulate while the component instance lives.
- **Class:** Resource leak (RxJS).
- **Fix:** Move the playback subscriptions to the constructor/`ngOnInit`, or recreate a per-timer `Subscription` inside `stopTimers()` before re-adding.

### BUG-005 — Progress interval never cleared (Low)

- **File:** `src/app/services/playback/playback.service.ts`, lines 790–809.
- **Symptom:** `startUpdatingProgress()` creates a 500 ms `setInterval` once (guarded by `_progressInterval === 0`). `stopUpdatingProgress()` → `pauseUpdatingProgress()` only sets `_shouldReportProgress = false`; it never `clearInterval`s nor resets `_progressInterval` to 0. Subscribers aren't spammed (the callback early-returns on the flag, 783–787), but the timer keeps waking every 500 ms for the app's lifetime.
- **Class:** Resource lifecycle.
- **Fix:** On stop, `clearInterval(this._progressInterval)` and reset `_progressInterval = 0`; keep pause as the non-emitting state.

### BUG-006 — Restored `orderId` used as array index without validation (Low)

- **File:** `src/app/services/playback/queue-persister.ts`, lines 101–105 (init 68).
- **Symptom:** `playbackOrder = new Array(savedQueuedTracks.length).fill(0)` then `playbackOrder[orderedTrack.orderId] = …`, where `orderId` is read raw from the DB (`queued-track-repository.ts` 18–25; no uniqueness/range constraint in `migration1.ts` 72–79). Duplicate IDs overwrite earlier entries (leaving zeros); out-of-range IDs create a sparse array. JS won't crash, but `Queue.tracksInPlaybackOrder` / `getNextTrack()` then duplicate, skip, or prematurely end restored playback. App-generated saves use valid indices, so this only bites on a corrupt/hand-edited DB.
- **Class:** Boundary / input validation.
- **Fix:** Validate restored order IDs are unique integers in `[0, n-1]`; otherwise rebuild a sequential order from `orderedTracks`.

### BUG-007 — LIKE operands don't escape `%` / `_` (Low)

- **Files:** `src/app/data/clause-creator.ts`, lines 32–34; same pattern in `src/app/data/smart-playlist-query-builder.ts`, lines 119–127 and 142.
- **Symptom:** The LIKE clause escapes single quotes but not the LIKE wildcards `%` and `_`, and adds no `ESCAPE` clause. A genre/artist/smart-playlist value containing those characters (e.g. `100% Pure`, `A_B`) matches more rows than intended. Inputs are stored tag values / smart-playlist rule text, not arbitrary free-text, which bounds the impact.
- **Class:** SQL correctness (search filtering).
- **Fix:** Escape `%`, `_`, and the escape character in the operand and append an explicit `ESCAPE` clause.

### BUG-008 — Log message not interpolated (Low)

- **File:** `src/app/services/indexing/track-filler.ts`, lines 137–142.
- **Symptom:** `'Error while retrieving ReplayGain tag information for file ${track.path}'` uses single quotes, so `${track.path}` is logged literally. Diagnostics-only; the track still records `indexingFailureReason` (134–135). Nearby logs use backticks correctly (32–37, 112–117); this was the only occurrence found in `src/app`.
- **Class:** Logic (string literal).
- **Fix:** Use a backtick template literal.

### BUG-009 — Theme-watch interval not idempotent (Low)

- **File:** `src/app/services/appearance/appearance.service.ts`, lines 175–179 (stop 181–183).
- **Symptom:** `startWatchingThemesDirectory()` assigns `this.interval = window.setInterval(…)` without clearing any existing interval. The only callers are `AppearanceSettingsComponent` `ngOnInit`/`ngOnDestroy`, so normal lifecycle pairs one start with one stop — but a second `start` without an intervening `stop` orphans the first interval (its id is lost).
- **Class:** Resource lifecycle (idempotency).
- **Fix:** Clear any existing interval before assigning a new one.

### BUG-010 — Unvalidated Discord IPC argument (Low)

- **File:** `main.ts`, lines 621–623.
- **Symptom:** `discordApi.setPresence(command.args!)` uses a non-null assertion on `args: PresenceArgs | undefined` with no validation/try-catch on the IPC boundary. Normal renderer code never sends `SetPresence` without args (`discord.service.ts` 120–132) and `setPresence(undefined)` is a no-op while Discord is not ready (`discord-api.ts` 56–63) — but a malformed command would dereference `args.title` (65–72) and throw in the main process.
- **Class:** Trust boundary / input validation.
- **Fix:** Validate `command.commandType` and require `command.args` before calling `setPresence`; log and ignore malformed commands.

### BUG-011 — Per-call DB connections, never explicitly closed (Low)

- **File:** `src/app/data/database-factory.ts`, lines 17–20 (same pattern in `main/background-work/data/database.factory.js` 9–12).
- **Symptom:** `create()` returns `new Database(file)` on every call and repositories call it per operation; no caller invokes `.close()`. better-sqlite3 is GC-backed (its README and native destructor close handles), so this is **connection churn + non-deterministic cleanup**, not the unbounded file-descriptor leak it first appears to be — hence Low.
- **Class:** Resource lifecycle.
- **Fix:** Prefer a single app-scoped connection, or wrap each operation in `try { … } finally { database.close(); }`.

## Rejected candidates (false positives)

Recorded for the audit trail — these were proposed by the static pass but
**disproven** during verification:

| Candidate | Why it's NOT a bug |
|-----------|--------------------|
| `queue.ts` `restoreTracks()` not cloning input | Only caller (`playback.service.ts` `restoreQueueAsync` 765–775) passes freshly built arrays from `QueuePersister.restore()` that are not retained or mutated afterward — no aliasing in practice. |
| `main.ts` `remoteMain.initialize()` called multiple times | It sits inside `createMainWindow()`, but on macOS `close` hides (not destroys) the window (291–307) and Windows quits on `window-all-closed` (458–464), so the `activate`→recreate path isn't reached in normal lifecycle. |
| `main.ts` `webContents` listeners never removed | Bound to the current window's `webContents`; the window is reused, not recreated, so listeners don't accumulate (and a destroyed `webContents` takes its listeners with it). |
| `main.ts` `nativeTheme.on('updated')` never removed | Registered once in primary-instance setup (512–518); an app-lifetime singleton listener — benign. |
| `ipc-proxy.ts` 6 `ipcRenderer.on` listeners never removed | `IpcProxy` is an Angular root singleton (`app.module.ts` 630) — one instance for the renderer's lifetime; listeners don't accumulate. |

## Recommended order of remediation

1. **BUG-002** (one-line bound-parameter fix; user-visible artwork failures on common album names).
2. **BUG-001** (crossfade users can get a stuck/ended-without-advance state).
3. **BUG-003** (worker `error` handler + terminate on quit; robustness).
4. Batch the Low resource-lifecycle items (BUG-004/005/009/011) together.
5. BUG-006/007/008/010 as opportunistic correctness fixes.
